# EU Hosting Path

Contractor.AI runs locally by default with SQLite and a local evidence directory. The Docker image is portable so the same build can run in an EU-region container platform.

Hosted mode is intentionally fail-closed. Set `CONTRACTOR_AI_RUNTIME_MODE=hosted` only after the deployment provides an HTTPS `CONTRACTOR_AI_PUBLIC_URL`, a strong `CONTRACTOR_AI_AUTH_TOKEN`, an EU S3-compatible evidence store, and a reachable managed PostgreSQL target in `CONTRACTOR_AI_DATABASE_URL`. The database URL must require TLS with `sslmode=require` or, preferably, `sslmode=verify-full`. At startup the ledger applies schema creation, versioned migrations, and legacy seeding under a PostgreSQL advisory lock; concurrent replicas wait on the same database connection boundary instead of applying a migration twice. A failed or timed-out startup closes that connection so the lock cannot survive the failed process. Hosted mode never falls back to a local SQLite file.

Production readiness also requires `CONTRACTOR_AI_HOSTING_PROVIDER`, `CONTRACTOR_AI_HOSTING_REGION`, `CONTRACTOR_AI_DATA_RESIDENCY=EU`, and a retained `CONTRACTOR_AI_DPA_REFERENCE`. These fields are operator declarations, not provider attestations; preserve the referenced contract and residency evidence outside the application. `CORS_ORIGINS` must include the exact public HTTPS origin.

Set `CONTRACTOR_AI_TRUST_PROXY` to the exact ingress source IP, CIDR range, or an intentionally selected Express subnet name visible to the container. Hosted startup fails without it. Boolean trust, numeric hop counts, wildcards, and universal CIDRs are rejected because path-length changes or a direct connection could otherwise let a caller spoof `X-Forwarded-For` and bypass per-client controls. Keep the application port loopback-bound, restrict container-network membership, and verify the observed ingress source after every proxy or network change. General API limits are atomically retained in SQLite or PostgreSQL so restarts and additional replicas do not grant a fresh quota. `CONTRACTOR_AI_RATE_BUCKET_LIMIT` bounds table cardinality: source addresses are HMAC-assigned to that fixed bucket space and are never stored directly. The minimal health probe remains available while a client bucket is limited.

Operators sign in through the application with an unpadded, non-template role access key containing at least 32 characters. Contractor.AI exchanges the key for a signed HTTP-only, `SameSite=Strict`, `Secure` cookie and does not retain the key in browser storage. A one-way session id hash is retained in PostgreSQL, allowing logout to revoke the cookie across restarts and replicas. Cookie-authenticated writes require an `Origin` that matches the request host or the explicit CORS allowlist, closing cross-site form submission paths. `CONTRACTOR_AI_SESSION_TTL_SECONDS` is bounded between 15 minutes and 24 hours; the default is eight hours. Failed sign-ins use a separate fixed-window limiter controlled by `CONTRACTOR_AI_LOGIN_RATE_LIMIT` and `CONTRACTOR_AI_LOGIN_RATE_WINDOW_MS`. Its HMAC-derived client key and atomic count are retained in the ledger, making the limit restart-persistent and replica-safe without storing the client address; successful authentication clears prior failures. Restore and local-to-hosted migration deliberately clear old login and API limiter rows so one environment's transient quota state is not copied into another. Rotate the underlying owner or role token to invalidate all sessions after suspected disclosure. API clients may continue to use bearer or API-key headers instead of a browser session.

Every retained audit event advances one SHA-256 chain head in the same SQLite or PostgreSQL transaction as the underlying change. PostgreSQL writers lock that one head row, so concurrent replicas cannot create two valid successors. `/api/readiness`, `/api/operations/capabilities`, and owner-only `/api/operations/audit-integrity` verify the retained sequence, event payload hashes, and head. A mismatch fails readiness; recover from a known-good provider recovery point instead of rewriting or silently re-chaining production history.

The evidence storage adapter uses the standard S3 API with `CONTRACTOR_AI_S3_ENDPOINT`, `CONTRACTOR_AI_S3_BUCKET`, `CONTRACTOR_AI_S3_REGION`, `CONTRACTOR_AI_S3_ACCESS_KEY_ID`, and `CONTRACTOR_AI_S3_SECRET_ACCESS_KEY`. Hosted endpoints must use HTTPS and cannot contain embedded credentials, query parameters, or fragments. Configure a private bucket, EU residency, encryption at rest, and the provider's DPA before use. Every retained reference is constrained to `CONTRACTOR_AI_S3_PREFIX`, preventing a ledger record from reading a sibling tenant prefix. Evidence is served through the authenticated ledger route, never from a public object URL.

Hosted startup performs a bounded PUT/GET/DELETE verification against a unique readiness marker under `CONTRACTOR_AI_S3_PREFIX`. The service does not listen when the bucket is unreachable, credentials are rejected, the marker cannot be read back, or the verified marker cannot be removed. `CONTRACTOR_AI_STORAGE_TIMEOUT_MS` bounds each object-store request and `CONTRACTOR_AI_STORAGE_VERIFY_TTL_MS` controls the verification cache. Grant the runtime only the object permissions it needs for the configured prefix. Docker probes the minimal public `/api/health/ready` endpoint; detailed runtime and provider state remains behind authenticated `/api/readiness` and `/api/operations/capabilities` routes.

Evidence retry receipts are stored in the same PostgreSQL ledger as the document record. Keep the application and database clocks synchronized: active upload leases prevent concurrent duplicate work, every processing attempt has a unique owner token, and stale attempts cannot complete or release a reclaimed receipt. Completed receipts replay exact retries for 24 hours without writing a second object. Reusing a key for a changed payload fails closed.

The optional autonomous scheduler also coordinates through PostgreSQL. Every due-cycle claim is an atomic compare-and-swap against the lease state the replica observed, and completion is accepted only from the current lease owner. Concurrent replicas may all poll, but only one can run a due cycle; a stale worker cannot overwrite the current owner's outcome. Cycles remain ledger-only and idempotent, and record zero external commitments.

For a controlled hosted staging run, copy `.env.hosted.example` to the non-committed `.env.hosted`, replace every placeholder, then run `docker compose --env-file .env.hosted -f docker-compose.hosted.yml up --build`. The explicit `--env-file` is required for Compose interpolation. Hosted Compose deliberately does not provision a database: point it at the same class of managed EU PostgreSQL service used in production, with encrypted connections, backups, point-in-time recovery, and a signed DPA. The Compose port binds to loopback only; place an EU-hosted HTTPS ingress on the same host in front of it and set `CONTRACTOR_AI_TRUST_PROXY` to that ingress connection's observed source. The container filesystem is read-only, Linux capabilities are dropped, and privilege escalation is disabled.

Declare recovery with `CONTRACTOR_AI_POSTGRES_BACKUP_MODE=snapshot` or `pitr`, `CONTRACTOR_AI_OBJECT_VERSIONING_ENABLED=true`, and a retained `CONTRACTOR_AI_BACKUP_POLICY_REFERENCE`. Readiness fails until all three are present. Exercise the referenced database restore and evidence-version recovery before production use and after material provider-policy changes.

Application-local backup endpoints intentionally return `409 provider_recovery_required` in hosted mode. The application cannot safely claim to have backed up provider-managed PostgreSQL and S3 data by writing files inside its container. The operational export remains available as a human-readable reconciliation artifact, but it is not a recovery image.

The local-first workflow uses SQLite. Hosted workflow uses PostgreSQL through the same ledger interface. Do not expose a local data volume publicly or treat an ephemeral serverless filesystem as operational storage.

Before a hosted migration, create `/api/operations/backup`, validate its restore readiness through `/api/operations/restore/validate`, verify its v2 manifest includes the expected evidence count and a valid audit chain, download the verified `tar.gz` package from `/api/operations/backups/:backupId/download`, and download `/api/operations/export`. Verify the export through `/api/operations/exports/validate`, then store both artifacts on encrypted off-device media according to the operator's retention policy. The export is a reconciliation record, not a recovery image. Local v2 packages checksum both SQLite and private evidence; they are not a substitute for managed PostgreSQL snapshots or hosted object-store versioning.

Stop the local runtime and keep the hosted application stopped. Point `CONTRACTOR_AI_DATABASE_URL` at a new, empty managed PostgreSQL database, configure the private S3-compatible variables, and run:

```powershell
npm run migrate:hosted -- --backup-id <backup-id> --confirm MIGRATE_<backup-id>
```

The migration accepts a verified backup manifest v2, not the summary JSON export. It requires PostgreSQL TLS, takes an exclusive migration lock, refuses any target containing operational rows, copies every durable business-ledger table in foreign-key order, upgrades PostgreSQL numeric columns to double precision, uploads every evidence file, and reads each object back before committing. Browser sessions are deliberately invalidated instead of migrating from the local machine. Retained local storage references inside document and JSON evidence records are rewritten to the hosted object references. A failed pre-commit database or object check rolls back rows and removes uploaded objects.

On success the target audit ledger contains a `migrate_local_backup_to_hosted` receipt with the source backup id, manifest checksum, database checksum, row count, table count, invalidated-session count, cleared authentication and API rate-limit counts, source audit-integrity result, and evidence checksums. Start the hosted application only after the receipt and `/api/readiness` both validate. The ledger exposes migrations through `031_cost_forecast_snapshots`; PostgreSQL must report no remaining 32-bit `real` columns, must include retained business identity and trade-partner compliance, idempotency lease ownership, revocable hashed browser sessions, durable hashed sign-in throttles, bounded replica-safe API request windows, a verified atomic audit chain, indexed owner audit-history queries, durable invoice, credit-note, purchase-order, change-order, and cost-forecast numbering, immutable issue packages and cost-forecast snapshots, generic OASIS UBL 2.1 Order exports with approval-gated verified provider delivery, scope-change acceptance bound to a checksum-verified issued package and provider receipt, source-linked cost-code forecasting that separates issued commitments from authorized spend and reduces linked order commitment by approved supplier invoices, exact receivable and supplier-payable reconciliation, unique payment reconciliation keys, contract-bounded approval-gated billing milestones with one-to-one invoice linkage, checksummed approval-gated critical-path schedule baselines with retained task dependencies, opportunity/activity tables with unique conversion and follow-up idempotency constraints, governed bid packages with immutable return comparisons, approval-gated preferred-bidder selections, and source-verified approval-gated purchase commitments, server-calculated quantity takeoffs with tamper-evident estimate conversion, controlled document identity and supersession indexes, approval-backed transmittal snapshots with recipient acknowledgment evidence, immutable approval-backed project meeting minutes with linked action tasks, carry-forward lineage, and delivery evidence, and reusable versioned inspection templates with immutable field submissions and linked corrective observations. It must also have revoked legacy active portal links owned by inactive jobs. Environment migration verifies chained source history when present, then rebuilds the destination chain because retained storage references change. Authentication and API throttle windows are intentionally cleared during environment migration. Retain the encrypted local package according to policy until hosted backups, point-in-time recovery, object versioning, and a restore exercise have all been verified.
